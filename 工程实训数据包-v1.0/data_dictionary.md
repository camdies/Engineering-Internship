# 数据字典 · 工程实训数据包 v1.0

---

## 一、数据库结构

`geodata-teaching.db` 是 SQLite 数据库，包含两张表：

| 表 | 行数 | 说明 |
|---|---|---|
| `datasets` | 20,000 | 数据集目录记录，**主表** |
| `data_sources` | 38 | 数据源注册表，含采集端点、更新状态、累计条数 |

本次**不提供**检索索引。

---

## 二、`datasets` 表：30 个字段

### 标识

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | TEXT 主键 | 形如 `pangaea_9d2ec73881c8`，前缀是数据源，后缀是内容哈希 |
| `title` | TEXT | 数据集标题 |
| `record_id` | TEXT | 数据源侧的原始记录号 |
| `doi` | TEXT | 数据集 DOI，**仅 27.1% 有值** |

### 内容

| 字段 | 类型 | 说明 |
|---|---|---|
| `description` | TEXT | 摘要。**被硬截断在 1000 字符**，见第四节警告 |
| `keywords` | TEXT | JSON 数组字符串，如 `["snow cover","glacier"]` |
| `data_type` | TEXT | 学科分类，10 个取值（见第三节） |

### 来源与溯源

| 字段 | 类型 | 说明 |
|---|---|---|
| `source_adapter` | TEXT | 采集适配器，11 个取值，如 `dataone`、`stac` |
| `source_paradigm` | TEXT | 采集范式标记 |
| `source_url` | TEXT | 数据源端点 |
| `providers` | TEXT | JSON 数组，数据提供者 / 作者姓名 |
| `discovered_at` | TEXT | 被采集到的时间，**不是数据本身的时间** |
| `search_query` | TEXT | 采集时使用的检索词 |
| `search_topic` | TEXT | 采集时归属的主题 |

### 时空

| 字段 | 类型 | 说明 |
|---|---|---|
| `spatial_bbox` | TEXT | JSON 四元组 `[minx,miny,maxx,maxy]`，**仅 16.6% 有值** |
| `spatial_crs` | TEXT | 坐标系，默认 `EPSG:4326` |
| `temporal_start` | TEXT | 时间起点，ISO8601 字符串 |
| `temporal_end` | TEXT | 时间终点，**语义不可靠**，见第四节 |

### 访问与合规

| 字段 | 类型 | 说明 |
|---|---|---|
| `distributions` | TEXT | JSON 数组，`[{"url":…,"format":…,"size_bytes":…}]` |
| `license` | TEXT | 许可协议，**仅 31.6% 有值** |
| `accessibility` | TEXT | 可达性状态，中文枚举（见下） |
| `last_checked_at` | TEXT | 最近一次可达性检查时间 |

`accessibility` 的 5 个取值及分布：

| 取值 | 条数 |
|---|---|
| `可达` | 8,280 |
| `未验证` | 8,117 |
| `弱可达` | 2,404 |
| `失效` | 921 |
| `需认证` | 278 |

注意设计上它是英文枚举（建表默认值是 `UNVERIFIED`），实际数据存的是中文——这是真实的不一致。

### 评分与排序

| 字段 | 类型 | 说明 |
|---|---|---|
| `confidence` | REAL | 采集置信度 |
| `citation_count` | INTEGER | 被引次数，**20,000 条全部为 0** |
| `cnci_score` | REAL | **整列全为 0，字段未启用** |
| `importance_score` | REAL | 重要性评分，0.175–1.66 |
| `is_core` | INTEGER | 核心数据集标记，本例中占 16.5% |
| `is_deleted` | INTEGER | 软删除标记 |

## 四、不可信字段清单

**做分析前务必先读这一节。** 下面这些字段直接用会得出错误结论。

| 字段 | 问题 | 后果 |
|---|---|---|
| `cnci_score` | 20,000 条**全部为 0** | 任何「影响力分析」都会得到空结果 |
| `citation_count` | 20,000 条**全部为 0**（引文表未填充） | 同上 |
| `temporal_end` | 大量记录存的是**元数据采集时刻**，不是数据覆盖终点 | 时间范围分析会得出「数据都覆盖到 2025 年」的假结论 |
| `description` | **硬截断在 1000 字符**，6,273 条命中上限 | 语义检索的天花板被人为压低；做摘要类任务要先说明这个边界 |
| `spatial_bbox` | 覆盖率仅 16.6%，且存在非法值 | 空间检索天然受限，需要说明边界 |
| `license` | 覆盖率仅 31.6% | 合规分析要区分「没声明」和「无限制」 |
| `providers` | 存的是真实人名（公开元数据） | 请勿用于任何数据包之外的用途 |
| `importance_score` | 打分方法未公开 | 可以拿来做排序实验，但不要当成权威重要性 |
| `search_query` / `search_topic` | 是**采集策略**的痕迹，不是数据本身的属性 | 不要用它来推断学科分布 |

## 六、抽样是怎么做的

**为什么不直接用全量？** 原库 129,388 条，其中 37,797 条来自 crossref，
是**文献记录而非数据集**（其中 35,978 条描述为空），已整源排除。
排除后可选池 91,591 条，本次抽取 20,000 条（21.8%）。

### 分层规则

1. **第一层按 `data_type`**：总量不足 1,000 条的类别（古气候、土壤土地、人文）**全取**；
   其余按比例分配。
2. **第二层按 `source_adapter`**：在每个学科内部按数据源比例分配，保证 11 个源都有席位
   （小源有保底，`emodnet-csw` 这种全库只有 13 条的也保留）。
3. **格内排序**：按 `id` 升序（`id` 后缀是哈希，等价于可复现的随机抽样）。
   **本次不做字段完整度倾斜**，以保证分布的统计代表性。

完整参数见 `sampling_config.json`。

### 教具记录：有意保留的缺陷样本

为了让第 1 层的质量审计任务有足够素材，缺陷记录被**强制纳入**，但总占比封顶在 12%：

| 缺陷类型 | 可选池总数 | 纳入样本 | 比例 |
|---|---|---|---|
| 空间范围非法 | 301 | 301 | 100% |
| 时间倒挂 | 969 | 969 | 100% |
| 未来日期 | 3,736 | 1,130 | 30% |
| 超长单元格样本 | — | 45 | — |

**这意味着样本里缺陷记录的密度高于自然水平**（缺陷合计占 12%）。做「数据质量有多差」这类
比例型结论时要考虑这一点。

### 字段覆盖率：与原库基本一致

| 字段 | 抽样覆盖率 | 可选池覆盖率 | 富集倍数 |
|---|---|---|---|
| 有描述 | 78.9% | 78.2% | 1.01x |
| 有关键词 | 60.0% | 59.9% | 1.00x |
| 有空间范围 | 16.6% | 14.6% | 1.14x |
| 有时间起点 | 51.6% | 49.2% | 1.05x |
| 有 DOI | 27.1% | 28.2% | 0.96x |
| 有许可 | 31.6% | 32.7% | 0.97x |

富集倍数都在 1.15 倍以内，**字段层面的分析结果可以直接使用**。

### 两处有意偏离，做分布分析必看

**第一，小类别被全量收入**，所以它们在本数据集中被显著高估：

| 学科 | 抽样 / 可选池 | 覆盖率 |
|---|---|---|
| 古气候 | 77 / 77 | 100% |
| 土壤土地 | 415 / 415 | 100% |
| 人文 | 524 / 524 | 100% |
| 水文 | 490 / 2,344 | 20.9% |

**第二，缺陷记录占 12%**，高于自然水平。

所以，凡是涉及「全球地学数据里有多少古气候数据」「数据荒漠在哪」这类**分布性结论**，
你有两个选择：

- 明确声明结论只针对本数据集，不推广到全球；
- 或者按上表的覆盖率做加权后再下结论。

两种做法都可以，**但不声明就是错的**。

## 七、JSON 字段怎么解析

四个字段存的是 JSON 字符串：`providers`、`keywords`、`distributions`、`related_publications`。

**Python：**

    import json
    keywords = json.loads(row["keywords"] or "[]")

**SQLite 直接展开：**

    -- 统计每个数据集有几个关键词
    SELECT id, json_array_length(keywords) AS n
    FROM datasets
    WHERE json_valid(keywords);

    -- 展开成一行一个关键词
    SELECT d.id, j.value AS keyword
    FROM datasets d, json_each(d.keywords) j
    WHERE json_valid(d.keywords);

`json_valid()` 一定要加——数据里有非法的 JSON，不加会直接报错中断查询。
